1. **引言**

**1.1 目的**

本文档定义校园互助服务平台（CampusHub）的功能需求与非功能需求，为后续设计、开发、测试提供依据。系统旨在为南京大学学生提供安全、高效、可信的互助服务，覆盖快递代取、学习辅导、二手交易、失物招领、拼车拼单、找搭子、组队等校园场景。

**1.2 范围**

系统核心功能（P0）：用户管理、需求发布与浏览、订单流程管理。

应做功能（P1）：评价与信用体系、消息通知。

可选功能（P2）：智能匹配推荐、管理后台、即时通讯。

**1.3 定义与缩略语**

| 术语 | 说明 |
| --- | --- |
| CampusHub | 校园互助服务平台项目名称 |
| 需求方 | 发布互助需求的用户 |
| 服务方 | 接单并提供帮助的用户 |
| 信用分 | 基于历史评价计算的用户信用值（0-100分） |
| 爽约 | 接单后无正当理由取消或未完成任务 |
| P0/P1/P2 | 优先级：必做/应做/可选 |

1. **总体描述**

**2.1 产品视角**

CampusHub 是一个 Web 应用，采用前后端分离架构。学生通过学号认证注册登录，可发布或承接互助任务，完成后双向评价，积累信用分。平台支持轻量级互助（如失物招领、找搭子）和交易类互助（如跑腿、二手）。

**2.2 用户特征**

| 用户类型 | 特征描述 |
| --- | --- |
| 普通学生 | 南大在校生，有快递代取、学习辅导、二手交易、失物招领、拼车拼单、找搭子、组队等需求 |
| 管理员 | 平台运营人员（可由志愿学生担任），负责内容审核、用户管理、纠纷处理 |

**2.3 约束**

- 10周开发周期，4人团队，人均约60小时
- 核心功能（P0）必须完成
- 需支持主流浏览器（Chrome、Edge、Safari）

**2.4 假设与依赖**

- 学号认证可对接学校统一认证系统（如无法对接，采用人工审核+学生证上传）
- 用户愿意在平台内完成沟通（但初期可跳转微信，后期迭代内置IM）
- 平台初期运营由志愿管理员支撑
