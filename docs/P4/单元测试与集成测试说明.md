## 九、前端测试策略

### 9.1 分层策略

测试按依赖复杂度和测试收益分层：

| 层级 | 覆盖模块 | 策略 | mock 要求 |
|------|---------|------|-----------|
| Layer 1 — 纯函数 | `format.ts` | 不 mock，直接测试输入/输出 | 无 |
| Layer 2 — 基础设施 | `client.ts` | mock 外部库（axios），测全路径 | `vi.hoisted` mock axios |
| Layer 3 — 展示组件 | DemandCard, PageTransition, ProtectedRoute | props → UI 断言，mock 路由 | mock router/navigate |
| Layer 4 — Hook | `useAuth` | 正常路径 + 越界路径 | mock AuthContext |
| Layer 5 — 页面 | 12 个页面组件 | 加载态/错误态/数据态，mock API 层 | mock API 模块 |

### 9.2 Mock 模式

**AuthContext mock（完整接口，禁止 `as any`）：**

```typescript
const mockAuth: AuthContextType = {
  user: null, accessToken: null, isLoading: false, isAuthenticated: false,
  login: vi.fn(), register: vi.fn(), logout: vi.fn(), updateUser: vi.fn(),
};
```

**用户 mock 数据（使用类型常量）：**

```typescript
import type { UserProfile } from '@/types';
const mockUser: UserProfile = {
  id: 1, nickname: 'test', studentId: '2024000001',
  creditScore: 70, role: 'student', showRealName: false,
  createdAt: '2026-01-01T00:00:00Z',
};
```

**vi.hoisted 模式（axios mock 必备）：**

```typescript
const { mockAxiosInstance } = vi.hoisted(() => {
  const instance = vi.fn();
  (instance as any).interceptors = { request: { use: vi.fn() }, response: { use: vi.fn() } };
  return { mockAxiosInstance: instance };
});
vi.mock('axios', () => ({ default: { create: vi.fn(() => mockAxiosInstance) } }));
```

## 十、前端测试关键技术问题

### 10.1 React 19 + renderHook 异常测试

React 19 下 `renderHook` 在 Hook 抛出异常时会同步抛出（而非存入 `result.error`），因此用 `expect(() => renderHook(...)).toThrow()` 而非 `expect(result.error).toBeDefined()`。

### 10.2 MUI Rating 在 jsdom 中不可点击

`pointer-events: none` 阻止了 `userEvent.click` 和 `fireEvent.click`。评价表单测试策略：验证提交按钮初始 disabled 态 + 评价表单渲染，跳过星号交互。

### 10.3 jsdom 缺少的浏览器 API

| API | 解决方式 |
|-----|---------|
| `scrollIntoView` | `Element.prototype.scrollIntoView = vi.fn()` |
| CSS 动画（emotion sx） | sx 生成的 CSS 类名不可 inline 断言，只验证结构 |
| number input 过滤 | jsdom 的 number input 过滤非数字字符（如 `-`），负数校验无法在 jsdom 测试 |

### 10.4 React 19 异步错误处理

事件处理器中异步 reject 会导致 vitest 报 unhandled rejection。用 `process.on('unhandledRejection', handler)` 临时屏蔽。

### 10.5 ESLint 测试文件注意事项

| 规则 | 常见违规 | 正确做法 |
|------|---------|---------|
| `no-explicit-any` | mock user `as any` | 用 `UserProfile` 类型常量 |
| `set-state-in-effect` | 同步 `setState` 在 effect 体 | lazy initializer 或移到 `.then()` 回调 |
| `only-export-components` | 组件文件导出非组件 | `allowConstantExport: true` |

## 十三、前端 CI/CD 流水线

配置在 `.gitlab/frontend.yml`，包含四个阶段：

```
install (pnpm ci) → lint (pnpm lint + pnpm check) → build (vite build) → test (vitest)
```

### 13.1 流水线优化

| 优化 | 说明 |
|------|------|
| 独立 install stage | 输出 `node_modules/` 作为 artifacts，后续 jobs 通过 `needs: [frontend-install]` 并行执行 |
| pnpm 安装 | lint/build/test 各 job 在 `before_script` 中安装 pnpm（`npm install -g pnpm`，约 3s） |
| JUnit 报告 | 测试结果以 JUnit XML 格式上传 |

### 13.2 CI 注意事项

- `node:lts` 镜像不自带 pnpm，需手动安装
- 测试文件中的 `as any` 会导致 CI ESLint 报错——每次提交前执行 `pnpm lint && pnpm check && pnpm test && pnpm build`
