# 演示说明

## 一、运行方式

### 1.1 前置条件

| 依赖 | 版本要求 | 验证命令 |
|------|---------|---------|
| Node.js | >= 18（推荐 LTS） | `node -v` |
| MySQL | 8.0+ | `mysql --version` |
| pnpm | 任意版本 | `pnpm -v`（前端构建工具） |

> **注意**：第一次运行前，将 `backend/.env.example` 复制为 `backend/.env`，并根据本地环境修改以下配置：
> - `DATABASE_URL` — 将 `password` 改为你的 MySQL 密码
> - `PHONE_ENCRYPTION_KEY` — 手机号加密密钥（任意字符串），**未设置则登录时会报错**
> - `JWT_SECRET` / `JWT_REFRESH_SECRET` — 开发环境可保留默认值

### 1.2 启动步骤

**第一步：初始化数据库**

```bash
# 确保 MySQL 已启动，创建数据库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS campushub CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

# 同步 Prisma schema 到数据库
cd backend
npm run prisma:push

# 填充演示数据（2 个用户，密码均为 test1234）
npm run prisma:seed
```

**第二步：编译 shared 包**（修改 shared 目录后必须重新编译）

```bash
cd backend/shared && npx tsc && cd ..
```

**第三步：启动后端服务**（需要两个终端）

```bash
# 终端 1 — Service-A（需求 + 订单，端口 3001）
cd backend && npm run dev:a

# 终端 2 — Service-B（认证 + 用户 + 评价 + 消息 + 通知，端口 3002）
cd backend && npm run dev:b
```

> 也可以使用 `concurrently` 同时启动：`cd backend && npx concurrently "npm run dev:a" "npm run dev:b"`

**第四步：启动前端**（终端 3）

```bash
cd frontend && pnpm dev
```

前端默认运行在 `http://localhost:5173`，Vite 开发服务器会自动将 `/api/*` 请求代理到对应的后端服务。

### 1.3 一键启动（开发环境快速启动脚本）

在项目根目录创建 `start.bat`（Windows）：

```batch
@echo off
start "MySQL" cmd /c "mysql -u root -p campushub"
cd /d D:\workspace\college-subject\2026-SEC-II\sec-ii-2026\backend
start "Service-A" cmd /c "npm run dev:a"
start "Service-B" cmd /c "npm run dev:b"
cd /d D:\workspace\college-subject\2026-SEC-II\sec-ii-2026\frontend
start "Frontend" cmd /c "pnpm dev"
```

## 三、核心演示路径

### 演示路径 1：需求浏览与搜索

**目标**：展示需求列表、筛选、搜索功能。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开 `http://localhost:5173` | 首页显示需求卡片列表（默认只显示"开放中"的需求） |

| 3 | 在搜索框输入关键词 | 列表按关键词实时搜索（带防抖） |

> **说明**：首页初始无数据时为空白状态，可以先通过演示路径 2 创建需求后再查看。

### 演示路径 2：完整订单流程（核心路径）

**目标**：演示从注册到完成订单的全流程，涉及两个用户协作。

**前置：使用不同浏览器或隐身窗口分别登录两个用户**

| 角色 | 登录方式 | 浏览器 |
|------|---------|--------|
| 张三（发布者） | `2024000001` / `test1234` | Chrome 普通窗口 |
| 李四（服务方） | `2024000002` / `test1234` | Chrome 隐身窗口 |

#### 步骤 1：张三创建需求

| 操作 | 说明 |
|------|------|
| 张三登录 → 点击底部"发布"按钮 | 进入发布页面 `/demands/new` |
| 填写需求信息 | 标题、描述、分类、报酬 |
| 可开启"紧急"或"匿名"开关 | 紧急标签为脉冲动画，匿名隐藏发布者 |
| 可选上传图片 | 逐张上传 |
| 点击"发布" | 需求创建成功，跳转首页 |

#### 步骤 2：张三查看刚发布的需求

| 操作 | 预期结果 |
|------|---------|
| 首页出现新卡片 | 状态标签显示"开放中" |
| 点击卡片 → 详情页 | 可看到完整需求信息，发布者可看到"删除"按钮 |

#### 步骤 3：李四接单

| 操作 | 预期结果 |
|------|---------|
| 李四（隐身窗口）登录 | 首页也能看到张三发布的需求 |
| 点击需求卡片 → 详情页 | 可见"接单"按钮 |
| 点击"接单" | 弹出确认对话框 |
| 确认接单 | 订单状态变为"进行中"，张三收到通知"李四接了你的单" |

#### 步骤 4：李四提交完成

| 操作 | 预期结果 |
|------|---------|
| 李四进入订单列表 `/orders` → "我承接的" Tab | 看到进行中的订单 |
| 点击订单 → 详情页 | Stepper 显示当前进度 |
| 点击"提交完成" | 订单状态变为"待确认"，张三收到通知 |
| 张三刷新订单详情页 | 看到"确认完成"按钮 |

#### 步骤 5：张三确认完成

| 操作 | 预期结果 |
|------|---------|
| 张三点击"确认完成" | 订单状态变为"已完成" |
| 李四收到通知 | "张三确认了完成" |

#### 步骤 6：双方互评

| 操作 | 预期结果 |
|------|---------|
| 张三进入订单详情 | 评价面板出现，可选择星级并写评价 |
| 张三评价 4★ | 李四信用分 +1（从 70 → 71） |
| 重复评价 | 返回 409 "已评价过此订单" |
| 李四进入同一订单详情 | 评价张三 5★ |
| 李四提交 5★ 评价 | 张三信用分 +3（从 70 → 73） |

### 演示路径 3：爽约与信用分惩罚

**目标**：演示服务方爽约导致信用分扣减和限制接单。

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 张三创建一个新需求 | 需求状态"开放中" |
| 2 | 李四接单 → 李四取消订单 | 李四信用分 71 → 61（爽约 ×1），张三收到通知 |
| 3 | 张三重新创建需求（原有需求恢复"开放中"） | 其他用户可以接单 |
| 4 | 李四接单 → 李四取消（爽约 ×2） | 李四信用分 61 → 51 |
| 5 | 李四接单 → 李四取消（爽约 ×3） | 李四信用分 51 → 41 |
| 6 | 李四尝试再接新单 | **403 "因频繁爽约，您已被限制接单"**（restrictedUntil 设为 15 天后） |
| 7 | 查看李四的个人主页 | 信用分显示 41 |

> **注意**：每次取消后张三需要重新创建需求或需求恢复开放状态，才能让李四再次接单。

## 五、API 快速验证

如果不通过前端，也可以直接使用 curl 验证核心接口：

```bash
# 1. 注册
curl -X POST http://localhost:3002/api/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"studentId":"2024999999","password":"test1234","nickname":"演示用户"}'

# 2. 登录（保存 token）
curl -s -X POST http://localhost:3002/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"studentId":"2024000001","password":"test1234"}' \
  | node -e "process.stdin.resume(); let d=''; process.stdin.on('data',c=>d+=c); process.stdin.on('end',()=>{const j=JSON.parse(d); console.log('Token:', j.data?.token?.slice(0,30)+'...'); process.env.TOKEN=j.data?.token})"

# 3. 创建需求（替换 TOKEN 为实际值）
TOKEN="<上面返回的token>"
curl -X POST http://localhost:3001/api/demands \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"title":"求带午饭","description":"南苑食堂，鱼香肉丝饭","category":"生活服务","reward":5}'
```
