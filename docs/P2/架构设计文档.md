# 架构设计文档

# 架构概览

基于选定的**前后端分离 + 后端经典三层（表现层/业务层/持久层）单体分层架构**，以下提供完整的架构概览和架构图。

CampusHub采用**B/S模式**，前端为单页应用（React/Vue），后端为单体应用（Node.js/Express 或 Spring Boot），前后端通过HTTP RESTful API通信。后端内部严格划分为三个逻辑层：

- **表现层（Controller）**：接收请求、参数校验、响应封装、异常处理。
- **业务层（Service）**：实现订单状态机、信用分计算、推荐算法、定时任务等核心逻辑。
- **持久层（Repository/DAO）**：封装数据库CRUD，使用ORM（Prisma/MyBatis-Plus）。

辅助模块包括**基础设施**（JWT、加密、文件存储、WebSocket）和**MySQL数据库**。

# 模块划分

## **模块划分与职责边界**

### **1. 前端模块（Frontend）**

- **职责**：提供用户交互界面，发送HTTP请求到后端API，展示数据。
- **子模块**：
    - 用户界面（登录/注册、个人资料、角色切换）
    - 需求界面（发布、列表、详情、筛选）
    - 订单界面（接单、确认完成、历史记录）
    - 评价界面（评分、评价展示）
    - 消息界面（通知列表、即时通讯聊天）
    - 管理后台界面（用户管理、需求审核、统计看板）
- **技术实现**：React/Vue + 状态管理 + HTTP客户端（axios）

### **2. 后端表现层模块（Controller）**

- **职责**：接收HTTP请求，参数校验，调用业务层，返回JSON响应。
- **子模块**：
    - UserController：注册、登录、获取/更新个人资料、角色切换
    - DemandController：发布需求、获取需求列表/详情、筛选
    - OrderController：接单、更新订单状态、获取订单历史
    - ReviewController：提交评价、获取评价列表
    - MessageController：获取通知列表、发送/接收聊天消息
    - AdminController：用户禁用、需求审核、统计数据
    - RecommendController：获取推荐需求列表
- **依赖**：依赖对应的Service层模块。

### **3. 后端业务层模块（Service）**

- **职责**：实现核心业务逻辑（状态机、信用分计算、匹配算法等），协调多个Repository。
- **子模块**：
    - UserService：用户注册/登录验证、资料更新、角色切换、信用分获取
    - DemandService：需求发布、列表查询（含筛选排序）、详情获取
    - OrderService：订单状态流转（含48小时自动确认定时任务）、防并发抢单（乐观锁）
    - ReviewService：评价提交、更新用户信用分
    - CreditService：信用分计算规则（基于评价、完成率等）
    - MessageService：站内信通知、聊天消息存储
    - AdminService：用户封禁、需求审核、统计查询
    - RecommendService：基于分类/地理位置/历史行为的推荐算法
- **依赖**：依赖各Repository模块，以及Service之间可以互相调用（如OrderService调用CreditService）。

### **4. 后端持久层模块（Repository）**

- **职责**：封装数据库CRUD操作，提供统一数据访问接口。
- **子模块**：
    - UserRepository
    - DemandRepository
    - OrderRepository
    - ReviewRepository
    - MessageRepository
    - NotificationRepository（站内信）
- **依赖**：仅依赖数据库模块（或ORM框架）。

### **5. 数据库模块（Database）**

- **职责**：数据持久化存储，提供事务支持。
- **表设计**：user, demand, order, review, message, notification, admin_log等。

### **6. 基础设施模块（Infrastructure）**

- **职责**：提供通用技术能力。
- **子模块**：
    - AuthProvider：JWT生成与验证
    - PasswordEncoder：Bcrypt加密
    - FileStorage：头像/图片上传
    - WebSocketServer：即时通讯（P2可选）
    - Scheduler：定时任务（订单自动确认）

## 技术选型

| **层次** | **选择** | **选择理由** |
| --- | --- | --- |
| **前端框架** | React 18 + TypeScript | • 生态成熟，组件化开发效率高• TypeScript 支持完善，适合与后端共享类型定义• AI（Copilot/LLM）对 React 代码生成准确率高• Vite 构建速度快，热更新提升调试效率 |
| **后端框架** | Express 5 + TypeScript | • 轻量、灵活，与 Node.js 原生契合• 中间件生态丰富（JWT、校验、日志等）• 配合 ts-node 或编译后运行，开发便捷• 学习曲线平缓，团队成员可快速上手• AI 对 Express 路由及中间件模式理解深刻 |
| **数据库** | MySQL 15 | • 关系型数据库，完美支持事务（订单状态、信用分一致性）• 支持 JSON 字段，便于存储需求扩展属性• 开源、稳定，与 Node.js 配合良好（pg 或 Prisma） |
| **ORM/数据访问** | Prisma | • TypeScript 优先，提供类型安全的数据库操作• Schema 定义清晰，AI 可自动生成模型及迁移文件• 自带关系查询、事务、原生 SQL 支持• 减少手写 SQL 注入风险，提升开发效率 |
| **缓存** | Redis 7 | • 用于存储 JWT 黑名单（登出后失效）、热点需求列表、推荐结果缓存• 减轻数据库压力，提升页面加载速度（可满足 <2秒要求）• 若时间紧张可暂不引入，直接查数据库也能满足校园级并发 |
|  |  |  |
| **认证与授权** | JWT (jsonwebtoken) + bcrypt | • 无状态认证，适合前后端分离• JWT 存储用户角色信息，简化权限校验• bcrypt 单向加密密码，满足安全非功能需求 |
| **参数校验** | Zod | • TypeScript 原生，与 Express 集成良好（zod-express）• 可从 schema 自动推导类型，减少重复定义• AI 生成校验规则准确，错误提示友好 |
| **日志与调试** | Winston + morgan | • morgan 自动记录 HTTP 请求日志• Winston 支持分级日志（info/error）及文件持久化• 便于答辩时展示系统运行情况，后期排查问题 |
| **定时任务** | node-schedule | • 实现订单 48 小时自动确认完成• 轻量级，无需外部依赖• 单体应用下直接集成，简单可靠 |
|  |  |  |
| **部署方式** | Docker Compose | • 一键启动后端、PostgreSQL、Redis（可选）容器• 环境一致性，避免“本地能跑，答辩机器不能跑”• 便于课程演示及评分老师快速验证• 可配合 docker-compose.yml 及前端构建镜像（或用 Nginx 托管静态文件） |
| **版本控制与协作** | Git + GitHub | • 团队 4 人并行开发，通过 PR 进行代码审查• 每阶段提交对应 tag（如 P1-requirements、P4-core-sprint）• 符合课程过程管理要求 |
